# Route coverage

This inventory maps the existing routes to the final product contract. Routes listed as partial have an implementation or interface in the repository and still require acceptance testing.

| Routes | Controls and backing code | Current coverage and remaining work |
| --- | --- | --- |
| `/`, `/home`, `/workspace` | Landing and workspace links, account drafts through `GET /api/theses` | Partial. Personal dashboard, action ordering, and editable home layout still need validation. |
| `/auth`, `/onboarding`, `/settings/*` | Local codes through `/api/auth`, preferences through `/api/account` | Demo codes are development-only. Production identity, verified wallet linking, recovery, and complete account closure are open. |
| `/explore`, `/gemini`, `/gemini/:ticker`, `/search`, `/calendar`, `/watchlists/*` | Mode-aware compatible topics, Gemini event/upcoming/recently-settled APIs, event details, search, calendar and watchlist APIs | Gemini public market browsing is implemented with separate replay fixtures, source timestamps, response hashes, contract prices, and Gemini-provided resolution fields. Thesis search is restricted to the current account or guest draft owner. The live API remains unqualified because outbound DNS failed from the development environment. Full reminder, export, sharing, and deep-link acceptance are open. |
| `/topics/:slug`, evidence detail, `/theses/:id`, history | Topic and evidence reads, ElevenLabs speech input/output, source-grounded research replies, draft save, confirm and version restore | Voice records only after user action, displays an editable transcript and source links, and can open a proposed range as an editable thesis draft. Research only loads a thesis owned by the active account or guest draft, limits model requests, and maps citations to supplied evidence cards. Thesis snapshots persist on create, save and confirm, and restore creates a fresh draft. Source revisions and research deltas remain open. |
| `/theses/:id/build`, compare, review, `/quotes/:id` | Payoff compiler, chart, USDC validation, quote request, exact table, allowance confirmation, Arc receipt verification and position synchronization | Replay and paper paths are available. Live acceptance now verifies the quote event, escrow fields, and payout schedule before recording; deployment, maker funding, source-family qualification, and finalization operations still gate live use. |
| `/wallet/*`, `/orders`, `/settings/connections` | Wallet connect, Arc configuration, Gemini OAuth PKCE connection, encrypted refresh/access tokens, active and historical Gemini order reads, explicit cancellation, latest-terms review/acceptance, and one-off limit order submission with server-side market, terms, and instrument-grid checks | OAuth app registration, encryption settings, and a linked account are required. Gemini order behavior is unqualified without real-account responses; authenticated WebSocket order streams/rejected events, production token storage, provider funding, and complete allowance/withdrawal reconciliation remain open. |
| `/portfolio`, `/positions/*`, `/activity`, `/transactions/:id` | Account/guest-scoped paper positions, live Arc receipt-backed position records, direct escrow status refresh, verified holder claims, position activity | Paper positions remain local simulations. Live acceptance and claim records are checked against Arc receipts and onchain position state. Resolver settlement automation, live deployment/funding, durable storage, exits, and audited valuation remain open. |
| `/alerts`, `/notifications` | Account-scoped alert creation/pause and inbox read/unread updates | Ownership checks, input validation, and missing-session responses are implemented. Scheduled evaluation, delivery reliability, and notification preferences still need implementation and end-to-end verification. |
| `/journal/*`, `/reports`, `/publish/:id`, `/shared/:token`, `/profile/:handle` | Journal views, reports API, sharing snapshots | Ownership and rationale redaction are enforced at snapshot creation. Collaboration, moderation, revocation, accounting export provenance, and profile controls remain open. |
| `/help/*`, `/support/*`, `/status` | Help articles, ticket API, integration status API | Partial. Support authorization, status evidence and incident lifecycle require completion. |
| `/maker/*`, `/ops/*` | Maker policy, settlement handler, Streams webhook | Partial. Multi-maker funding and caps, curation, resolver review, and a deployed Stream need qualification and operational acceptance tests. |

Automated tests currently cover payoff compilation and comparison. The [qualification record](qualification.md) tracks external evidence. The [product contract](PROJECT_SPEC.md) defines the remaining control-level acceptance requirements.
